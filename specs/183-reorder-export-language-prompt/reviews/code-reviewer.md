## Code review for spec 183

Scope: `ExportLanguagePrompt.tsx` (new), `ExportLocalePicker.tsx`, `ReorderSection.tsx`, `PhoneOrdering.tsx`, and the `section.reorder.exportLanguagePrompt.*` additions in the three catalogs. I read the working-tree files and spot-checked the tests. I had no shell, so I could not run `git diff` or the gates. Everything below comes from reading the files, and the gate results are the developer's.

Verified against the review focus:
- **Fidelity to `## Backend design`:** The implementation matches it, and the implementation notes' "no deviations" holds. The prompt contract is as designed (§1b): mount = open, once-guard, synchronous confirm, every dismiss routes to `cancel`, and a store-id mismatch renders null and cancels. The desktop sites follow §2, the phone root owns the state and run functions per §3, and the native handoff is 350 ms.
- **`ExportLocalePicker` defaults:** Unchanged for the spec-139 call sites. With no new props, `segments === SEGMENTS`, the compact style object is the spec-139 shape (`paddingHorizontal 8`, `paddingVertical 3`, `borderLeft` by index), `fontSize` is 9.5, the label falls back to `chrome.localeSwitcher.aria`, and no `testID` is emitted. The divider index is correctly the filtered index. The four original tests are untouched and the five additions are all additive.
- **Hooks above the early return in `PhoneOrdering`:** Yes. All new `useStore`, `useLocale` and `useState` calls and both `useEffect`s (L712-790) sit above the `!currentStore?.id` guard (L921). `ExportLanguagePrompt` also keeps every hook above its own `if (storeMismatch) return null`.
- **Snapshot before the first await, and record → clear ordering:** All six sites call `exportSnapshot(currentStore, reorderPayload)` synchronously, before their first `await`, and from the same values the file is built from. At every site the tail is `if (ok|shared) { void record?.().catch(...); clear(...) }`, with record first, not awaited, and clear second. Desktop quick-order calls it after `setBusy(true)` but before any `await`, which is fine. The `!reorderPayload || !currentStore` no-op guard is present at all six.
- **Inline colors:** None in non-test code. The files use `C.accent`, `C.accentFg`, `C.border` and the other tokens. No direct Supabase calls, no `window.confirm` or `Alert.alert`, no web-only API reachable on native, and no legacy files touched. `app.json` is not in the diff.
- **Catalogs:** The same eight keys sit at the same position in all three. The es and zh-CN copy matches the architect's suggestions, and `formatQuickOrder` is consistent with the existing `quickOrderDialogTitle` in each locale.

### Should-fix
- `src/screens/cmd/sections/ReorderSection.tsx:591` and `src/screens/cmd/sections/phone/PhoneOrdering.tsx:865` — The "does this vendor's CSV go to the US Foods / SYSCO import file?" check is written out twice, in two components. Each copy is `pickImportVendor(narrowReorderToVendor(payload, vendor), vendorsList)`, and `runCsv` repeats it a third and fourth time. This spec added the press-time copies. Those two copies decide whether to show the prompt (AC-4), and `runCsv` independently decides which file to emit. If they drift, the prompt will appear for a file that has no language, or the reverse. Fix: add a small exported helper next to `narrowReorderToVendor`, for example `hasImportFormat(payload, vendor, vendors): boolean`. Use it in `onCsvPress`, `requestExport` and optionally the `runCsv` branch.

### Nits
- `src/screens/cmd/sections/ReorderSection.tsx:553`, `:403` — The local state is named `prompt`, which shadows the browser global `window.prompt`. AC-20 explicitly rules `window.prompt` out, so the name invites confusion. Phone uses `exportPrompt`. Consider `pendingPrompt`, or `exportPrompt` to match phone.
- `src/screens/cmd/sections/ReorderSection.tsx:555-560` — The "Security review (2026-08-08) ... Captured via `exportSnapshot`" comment now sits above `runCsv` and mostly restates the doc on `exportSnapshot` (L154-160). Trim it to one line, or point at `exportSnapshot`.
- `src/components/cmd/ExportLanguagePrompt.tsx:92-109` — `cancel` depends on `onCancel`, which every host passes as an inline arrow. So `cancel` changes on every render and the `[storeMismatch, cancel]` effect re-runs each render. It is harmless because the effect only acts on mismatch and `firedRef` guards it. Holding `onCancel` in a ref, or keying the effect on `storeMismatch` alone, would make the dependency array honest.
- `src/components/cmd/ExportLanguagePrompt.tsx:69` — The comment says `(see "Store switch" above)`, but the header bullet is titled "STORE SWITCH CLOSES IT". Align the wording.
- `src/components/cmd/ExportLanguagePrompt.tsx:206-208` — "REMOVABLE (owner did not ask for it)" is project-process state rather than a "why". Once the owner decides, replace it with a plain reason ("so a zh-CN user doesn't read the missing 中文 option as a bug") or delete the block.
- `src/components/cmd/ExportLanguagePrompt.tsx:43` — `ALL_LOCALES` duplicates `SEGMENTS` in `ExportLocalePicker.tsx:27`. `Locale` has no runtime list in `src/i18n/index.ts`, so either is acceptable. If one is exported (for example `EXPORT_LOCALE_SEGMENTS` from the picker), the other becomes a re-use.
- `src/components/cmd/ExportLanguagePrompt.tsx:190,203` — The same `aria` string is used for the sheet's `accessibilityLabel` and the radiogroup's label. A screen reader announces "Choose export language" twice in a row. The design asked for it, so this is optional. The radiogroup could use a shorter label, or the sheet could use the `title` key.
- `src/components/cmd/ExportLocalePicker.tsx:3-9` — The header still describes "a controlled 3-segment control". It is now 2-3 segments, with `size` and `options` mentioned only further down. A one-word tweak would do.
- `src/screens/cmd/sections/ReorderSection.tsx:405-409` vs `:588-605` — The quick-order `onPress` checks only `currentStore?.id`, while the CSV and PDF presses check `reorderPayload && currentStore`. `runQuickOrder` re-checks both, so this is safe. It is just inconsistent, and the prompt could open and then silently do nothing.
- `src/screens/cmd/sections/ReorderSection.tsx` / `PhoneOrdering.tsx` (out-of-scope) — The 130-character `void recordExportedOrder?.(...).catch(console.warn ...)` line plus the clear is now copy-pasted at six sites, and `runQuickOrder`'s code/name resolver block is duplicated between desktop and phone. Both are pre-existing and the design deliberately kept them. A `recordThenClear(vendor, exportedAt)` helper would pin spec 156 AC-10 in one place. This is a candidate for a follow-up spec.
- `src/screens/cmd/sections/phone/PhoneOrdering.tsx:798` (out-of-scope) — Phone `runQuickOrder` has no `busy` guard or `try/finally`, unlike the desktop version. After a confirm, the manager can reopen the sheet and fire another export while the first share is pending. This is pre-existing behavior and is not covered by AC-16 (desktop only).
- `src/screens/cmd/sections/phone/__tests__/PhoneOrdering.exportLanguagePrompt.spec183.test.tsx:351` — `'zh-CN' as any` is unnecessary, because the literal already satisfies `Locale`. The other `as any` casts in the new tests follow the spec-156 precedent.
