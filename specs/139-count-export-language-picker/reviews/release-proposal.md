## Findings summary
- **code-reviewer**: 0 Critical, 2 Should-fix, 3 nits. Should-fixes are both dead-i18n-key hygiene: (1) `noItemsToExport` added to all three catalogs but never wired — neither section guards an empty export, so exporting with zero countable items silently downloads a header-only CSV (PDF has a *different* `noItems` fallback); (2) `section.inventoryCount.export.colVendor` / `.groupVendor` are copy-paste leftovers from the EOD block (Inventory is grouped by category only). Nits: duplicated `onExportCsv/onExportPdf` + `parseCount` across the two sections, and a cross-file `Locale`-import style drift — all consistent with the spec's "stays in the section, mirrors ReorderSection" design. Positively verified: BOM blast radius is bounded (no re-import path consumes IMR's own exports), `en` byte-identity holds end-to-end, the export picker is component-local and never calls `setLocale`, and no `supabase.from/rpc` reaches the export path.
- **security-auditor**: 0 Critical, 0 High, 1 Medium, 1 Low. Medium — `buildCountCsv` has no CSV formula-injection guard (`=+-@`/tab/CR-leading cells in item name, category, group label, and the free-text operator **note** column are passed raw to `Papa.unparse`; CWE-1236). Rated Medium not High because it is an admin-only surface, Excel warns before DDE, and it mirrors an already-accepted gap in `reorderExport.ts` — so it is a *new* surface, not a regression. Low — the pre-existing `reorderExport.ts` parity, explicitly out of scope. Cleared: HTML injection in `buildCountPdfHtml` is fully mitigated (every interpolated value escaped via the inline 5-char `escapeHtml`), no secrets, no new data access, no PII in logs, BOM change is safe (single owner at the download seam, no double-BOM).
- **test-engineer**: full `npx jest` green (136 suites / 1427 tests / 2 snapshots, real exit 0); `tsc --noEmit` and `tsc -p tsconfig.test.json --noEmit` both exit 0. All localized-content, CSV-BOM, column-set, blank-cell, and filename ACs PASS with jest pins. Two ACs marked NOT TESTED at the jest layer (EODCountSection / InventoryCountSection render the CSV+PDF buttons) — source-correct, closeable with one section-level integration test each. PDF glyph rendering is a spec-sanctioned deferral to the browser pass, not a jest gap. Test-engineer explicitly concludes none of the three gaps are Critical by the pipeline's definitions.
- **backend-architect (post-impl)**: not invoked for this spec (frontend-only; the architect's design doc resolved all five open questions up front and confirmed N/A across DB/RPC/edge/RLS/realtime/migration). No drift review file present, consistent with no backend surface.

**Main-session browser verification (release-coordinator evidence — closes the jest NOT-TESTED gaps):** Logged into the local app and drove BOTH count screens. Each shows the EN/ES/中文 picker + CSV + PDF buttons (closes the two "button render" NOT-TESTED ACs with live evidence). On EOD count, set picker to 中文 and clicked CSV: captured the downloaded blob — headers rendered in Chinese (供应商,分类,项目名称,单位,箱规,标准量,已数箱数,已数单位数,已数总计,备注), item names localized, and raw bytes start with `EF BB BF` (UTF-8 BOM, `isBOM:true` confirmed) so Excel renders Chinese correctly. PDF HTML carries the charset + CJK font stack + real Chinese glyphs (jest-verified at source level). `en` export stays byte-clean English. Inventory count screen carries the identical toolbar.

**CI posture:** Both active gates were green on `main` at 438f09a. Spec 139 is **frontend-only — NO DB migration** (`src/utils/countExport.ts`, `ExportLocalePicker.tsx`, two section files, `downloadCSV`, i18n catalogs). Unlike spec 138, there is **no prod-apply step and no `db-migrations-applied.yml` exposure** — that gate cannot be perturbed by this changeset. A post-push confirmation of `test.yml` on `main` remains required per the standing CI rule once the commit lands.

## Recommended next steps (ordered)
1. **Commit and deploy.** No Critical, no broken AC, CI green, no migration to push. Ship-ready as-is.
2. **(Recommended pre-commit polish — optional, zero behavior risk) Prune the 2 dead-key sets** [code-reviewer Should-fix]. Drop `section.inventoryCount.export.colVendor` / `.groupVendor` from en/es/zh-CN, and for `noItemsToExport` either wire the empty-export guard (mirroring `ExportCsvDrawer.tsx:63-66`) or drop the key from all three catalogs. These files are already in this commit; landing dead keys is avoidable and the parity test stays green either way. Bundle now if the user wants a clean commit; otherwise fold into step 3.
3. **(Follow-up, do next — Medium) Add `sanitizeCsvCell()` to `buildCountCsv`** [security-auditor Medium]. Prefix any string cell whose first char is `=`/`+`/`-`/`@`/tab/CR with a leading apostrophe (string columns only; leave numeric cells summable). This is the highest-value follow-up: a new export surface that additionally carries a free-text `note` column under a cross-tenant stored-payload threat model. Non-blocking (mirrors an accepted gap, admin-only, Excel warns first) but worth a fast-follow spec. Mirror into `reorderExport.ts` in the same follow-up to close the Low.
4. **(Follow-up — test hardening) Add one section-level render test per screen** [test-engineer gap]. Mount EODCountSection / InventoryCountSection with a minimal fixture, assert the `eod-export-csv`/`eod-export-pdf` (and inventory equivalents) testIDs render, press CSV, and spy on `downloadCSV` for a `countExportFilename(...)` match. Closes the two NOT-TESTED render ACs at the jest layer so a future refactor can't silently rewire the buttons.
