### Should-fix
- `src/components/cmd/StockStoreDialog.tsx:74-96`, `src/screens/cmd/sections/BrandsSection.tsx:1204-1209` and `:1240-1248` — a late result can land on the wrong brand's tab. The dialog's `close` is blocked while a run is in flight, but the parent's `[brandId]` effect (L1205) unmounts the dialog with `setStockTarget(null)` regardless. The in-flight `submit` still resolves and calls the old `onStocked`, which calls `showStockPanel` and sets a panel for brand A while the tab shows brand B. The panel generation guard doesn't help, because `showStockPanel` bumps it itself. Fix: in `submit`, track an `isMounted` ref and skip `onStocked` and `onClose` when unmounted, or have `onStocked` compare the report's brand to the current `brandId`. The write did succeed, so the store reload still happens in the slice action. Only the stale panel is wrong.
- `src/components/cmd/StockStoreDialog.tsx:23` and `src/utils/stockResult.ts:49` — `plural` is defined twice with the same body. Export it once, from `stockResult.ts` or a small util, and import it. Related: line 312 calls `plural(n, 'of those', 'of those')` only to get "N of those" prefixed, which reads as a misuse. Write `${n} of those` directly.
- `src/components/cmd/StoreFormDrawer.tsx:472-478` — the "Stock from" list gives no INACTIVE marker, but the dialog does (StockStoreDialog.tsx:276-278). `StockSourceOption` carries `status` and the design includes inactive stores. An admin can pick a deactivated store as the source with no cue at create time. Show the same badge, or put it in `detail`.
- i18n convention (dialog, drawer, panel). `StockStoreDialog.tsx`, the new drawer block (StoreFormDrawer.tsx:458-532), the `StoresTab` panel and all of `stockResult.ts` are hardcoded English, with about 40 new user-facing strings. The spec (section 6) and the dev notes defend this as "matching neighbours", and the premise is only half true. `StoreFormDrawer` and the `StoresTab` JSX are indeed English-only, but `BrandsSection.tsx` already uses `useT()` elsewhere (L79, L406, L856, L1072), and 31 other cmd components use it. The same feature already ships three-locale strings in the EOD and audit surfaces, so an es or zh-CN admin gets a half-translated feature. The bigger cost is structural. `stockResult.ts` builds sentences by concatenation with English pluralization (`'row is'`/`'rows are'`, `'it won’t'`/`'they won’t'`, `has`/`have`), which can't be moved to catalog keys without redesign. The longer this sits, the larger the later i18n pass (already on the backlog for InventoryCatalogMode). Recommendation: either accept it as a known follow-up and say so in the release proposal, or move the dialog and result lines onto keyed strings with `{count}` interpolation and the `pluralKey` pattern from BrandsSection.tsx:45. This is a judgment call because the spec explicitly sanctioned it. I rate it Should-fix because it deviates from the repo norm for a new component, not because anything is broken.

### Nits
- `src/screens/cmd/sections/BrandsSection.tsx:1221` — `showStockPanel` runs the D-15 pair (`fetchInventory(storeId)` with its embeds, plus `fetchVendors`) even when the run added nothing (the "already has everything" path can't reach it, but a run with only skipped ticks can). Skip it when `itemsCopied + extrasAdded === 0`, since no link was added. The warning also repeats on any later run.
- `src/utils/stockResult.ts:162-184` — `vendorsMissingCustomerNumber` re-derives the `importCustomerNumbers[storeId] || accountNumber` rule that `vendorImportShared.ts:82` owns, in negated form, and the item-to-vendor fallback that EODCountSection owns. The comments cite both. Each is a drift point if the fallback changes. Not worth a refactor now. A one-line cross-reference in `vendorImportShared.ts` would catch it.
- `src/components/cmd/StockStoreDialog.tsx:308` — "{itemsAlreadyAtTarget} of {itemCount} are already at …" reads "1 of 1 are". Pluralize the verb, as the next line already does.
- `src/components/cmd/StockStoreDialog.tsx:226-229` — a failed preview has no retry control, only "Close this and try again". Acceptable, but the drawer's equivalent (StoreFormDrawer.tsx:528-532) at least lets creation continue.
- `src/components/cmd/StoreFormDrawer.tsx:148-151` — while a create is in flight, CANCEL, Esc and the sheet dismiss silently do nothing. The CANCEL button isn't visually disabled, unlike the dialog's (`disabled={submitting}` at StockStoreDialog.tsx:175). Add `disabled` and the same 0.6 opacity so the press doesn't look broken.
- `src/components/cmd/StoreFormDrawer.tsx:200` — "Created store" toasts before the stock run, so a failed stock shows a success toast and then a warning panel. The panel line "was created but not stocked" covers it. Consider toasting after stock, or leaving it as is, since the store did get created.
- `src/store/useStore.ts:3598-3600` — `void get().loadFromSupabase(...)` relies on `loadFromSupabase` never rejecting. It has its own catch today, so this is fine. Pin it with a comment if that is ever relaxed.
- `src/components/cmd/StockStoreDialog.tsx:98-99` — `closeRef` is assigned every render to feed the Escape handler. Same pattern as the drawer, so consistent. (Out-of-scope) The two files could share a small `useEscape` hook.
